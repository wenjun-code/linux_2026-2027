# Теоретическое введение

Системы контроля версий (Version Control System, VCS) применяются при
работе нескольких человек над одним проектом. При внесении изменений в
содержание проекта система позволяет их фиксировать, совмещать изменения
разных участников и выполнять откат к любой более ранней версии.

В классических (централизованных) системах используется единый
репозиторий, доступ к которому предоставляется через сервер. В
децентрализованных системах, к которым относится git, каждый участник
имеет полную копию репозитория вместе со всей историей изменений, что
позволяет работать автономно и синхронизироваться по мере необходимости
\[1\].

Основные понятия git: хранилище (репозиторий), коммит (фиксация
состояния), история (последовательность коммитов), рабочая копия (файлы
в текущем каталоге). Работа с командами оболочки и перенаправлением
вывода подробно рассмотрена в \[2\].

## Базовая настройка git

Заданы глобальные параметры: имя пользователя, адрес электронной почты,
поддержка UTF-8 в именах файлов, имя начальной ветки, настройки
обработки переносов строк:

``` bash
git config --global user.name 'Чжан Вэньцзюнь'
git config --global user.email wenjun-code@users.noreply.github.com
git config --global core.quotepath false
git config --global init.defaultBranch master
git config --global core.autocrlf input
git config --global core.safecrlf warn
git config --global --list
```

## Создание ключей SSH

Сгенерированы два ключа: RSA длиной 4096 бит и Ed25519. Параметр `-N ''`
задаёт пустую фразу-пароль, параметр `-q` отключает вывод случайного
рисунка:

``` bash
ssh-keygen -t rsa -b 4096 -C wenjun-code@users.noreply.github.com -f ~/.ssh/id_rsa -N '' -q
ssh-keygen -t ed25519 -C wenjun-code@users.noreply.github.com -f ~/.ssh/id_ed25519 -N '' -q
ls -l ~/.ssh
```

## Создание ключа PGP

Ключ создан в пакетном режиме с алгоритмом RSA 4096 бит, назначением
`sign` и бессрочным сроком действия:

``` bash
gpg --batch --pinentry-mode loopback --passphrase '' \
    --quick-gen-key 'Чжан Вэньцзюнь <wenjun-code@users.noreply.github.com>' rsa4096 sign 0
gpg --list-secret-keys --keyid-format LONG
```

Отпечаток созданного ключа: `24299B5D6A1430222C7F881072F4C76DCD8F1C14`,
идентификатор `72F4C76DCD8F1C14`.

## Настройка подписи коммитов

Указан ключ подписи, включена автоматическая подпись всех коммитов:

``` bash
git config --global user.signingkey 24299B5D6A1430222C7F881072F4C76DCD8F1C14
git config --global commit.gpgsign true
git config --global gpg.program /usr/bin/gpg
```

# Контрольные вопросы

**1. Что такое системы контроля версий (VCS) и для решения каких задач
они предназначаются?**

VCS — программное обеспечение для управления изменением версий
документов и кода. Решает задачи хранения истории изменений, совместной
работы, отката к предыдущим версиям, ветвления разработки и резервного
копирования.

**2. Объясните понятия VCS и их отношения: хранилище, commit, история,
рабочая копия.**

Хранилище (репозиторий) — база данных версий проекта. Commit — фиксация
состояния файлов, сохраняемая в хранилище вместе с автором, датой и
сообщением. История — последовательность коммитов, связанных отношениями
«родитель — потомок». Рабочая копия — файлы проекта в текущем каталоге,
из которых вносимые изменения попадают в коммит.

**3. Чем отличаются централизованные и децентрализованные VCS?**

В централизованных (SVN, CVS) существует единое хранилище на сервере, а
у пользователей — только рабочая копия. В децентрализованных (git,
Mercurial) каждый пользователь получает полную копию хранилища с
историей, поэтому может работать автономно.

**4. Действия с VCS при единоличной работе с хранилищем.**

Инициализация хранилища, создание файлов, добавление изменений в индекс,
фиксация коммитов, просмотр истории, при необходимости — откат к
предыдущей версии.

**5. Порядок работы с общим хранилищем.**

Получение актуальной версии (`git pull`), создание ветки под задачу,
внесение изменений, фиксация коммитов, отправка в удалённое хранилище
(`git push`), создание запроса на слияние и разрешение конфликтов.

**6. Каковы основные задачи, решаемые git?**

Управление версиями, ветвление и слияние, распределённая работа,
хранение истории, тегирование выпусков.

**7. Назовите и дайте характеристику командам git.**

`init` — создание хранилища; `clone` — копирование удалённого хранилища;
`add` — добавление в индекс; `commit` — фиксация; `push` и `pull` —
обмен с удалённым хранилищем; `branch` и `checkout` — работа с ветками;
`merge` — слияние; `log` — история; `status` — состояние рабочей копии.

**8. Примеры работы с локальным и удалённым репозиториями.**

Локально: `git init`, `git add .`, `git commit -m 'первый коммит'`. С
удалённым: `git remote add origin <url>`, `git push -u origin master`,
`git pull`.

**9. Что такое и зачем нужны ветви (branches)?**

Ветвь — независимая линия разработки, ответвлённая от основной истории.
Ветви позволяют разрабатывать функции и исправления изолированно, не
нарушая стабильность основной ветки, и затем сливать результаты.

**10. Как и зачем можно игнорировать некоторые файлы при commit?**

С помощью файла `.gitignore`, в котором перечисляются шаблоны имён
файлов и каталогов. Игнорируются временные файлы редакторов, объектные
файлы сборки, зависимости, файлы с секретами и локальные конфигурации.
